# 配音全文同步字幕

2026-10-14老板指出E001只有要点文字，要求以后带人讲解的视频有字幕。本规则适用于所有启用配音的装修视频分类；补充原配音模块，不另建制作流程。章节标题不是字幕，旁白或字幕文件也不能替代MP4里的可见字幕。

## 内容、同步与排版

- 中文字幕精确覆盖全部实际口播，允许改变分句/标点显示，不允许漏句或只留摘要；每条对应准确、自然的英文翻译。中文在上、英语在下，数字、术语和判断条件不能省略。
- 先定稿逐短句中英字幕，连同口播、封面、双语描述、两套五话题整包冻结并轻抖检测。只改断句/时间、不改字时保存一致性证据；新增英文、改字或补句使旧检测失效，须整包复检。
- 用最终纯声的强制对齐派生cue，记录准确语句ID。cue使用最终视频时间，加入音轨在HyperFrames中的真实起点（包括首帧偏移）；不能沿用变速前时间或把长口播机械等分。
- 中文优先一行，约8–16字短句只是起点，复杂内容可两行；英语一至两行。按语义、实际语速、手机阅读量分句，不逐字闪烁、不将整段话塞满屏。
- 字幕采用正文系统的清晰常规中文说明字体（苹方）与Avenir英文；1080画布中文48–52px、英语34–38px起试，360px检查真实阅读。宋体短主题可保留但与字幕错峰，不堆章节标题、要点说明、全文字幕三层信息。
- 逐镜找自然留白，通常在下方但不能沉入抖音底部描述区。必要时小面积中性浅白半透明衬底，不加整幅遮罩、阴影、模糊或厚底板；避让家具、同源细节窗及定位对象。无空位先改镜头/分句，不能无限缩字。
- 图片及细节仍随讲解推进，加字幕不代替相关画面。正常讲话期间不能人为留“无字幕观看时间”，只在真实停顿隐藏。同步误差目标≤0.3秒，实核后才记录达标。

## 原合同的追加字段

启用配音的新制作/正式返工在原 `narration` 内增加：

```json
{"subtitles":{"enabled":true,"mode":"burned_in_bilingual","policy_version":"narration-bilingual-full-v1","cues_path":"narration-subtitles.json"},"evidence_sha256":{"subtitles.cues_path":"<真实字幕文件SHA-256>"}}
```

字幕JSON包含 `policy_version`、`audio_offset_seconds`、原音频/口播/语句时间文件的 `audio/text/timing` 路径SHA与字节数，以及 `cues[]`：唯一 `id`、`line_id`、视频时间 `start/end`、`zh/en`。采用原pin格式，不另造消费账或视频合同。中文cue按每条语句依序串联后须与冻结口播一致（忽略分句标点，不忽略数字或词语），全部语句覆盖。

HyperFrames内用实际可见的 `.narration-subtitle.clip`，`data-cue-id`对应cue、`data-start/data-duration`对应时间，正文分别为 `.subtitle-zh/.subtitle-en`；原暂停时间线驱动显示。禁止用隐藏文字骗检查。SRT/VTT可附交，但不能替代烧录字幕。

`narration_contract.py`最终门检查字幕开启、文件指纹、全口播覆盖、中英非空、语句引用、唯一ID及时间。结构通过不等于画面可读或同步：最终MP4逐cue抽稳定中点，再核首/末句、长句及切点，检查真实字形、语言、漏句、位置与同期；实际无字幕即HOLD。完整审听与独立验收分别记录，不伪造PASS。

旧冻结交付、QA和outbox不追改，也不倒填字幕已通过。当前E001缺字幕已定位；获当前视频返工授权后沿原task新run补字幕，保留原声、音乐、照片、时长，不重复消费选题/风格/音乐。本轮先更新未来规则，未重渲染原视频。
