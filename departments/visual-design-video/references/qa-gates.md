# 图片与视频质检门

## 共用门禁

- 公司名称、服务、地区、价格、保修、CTA 和联系方式均有证据；
- 真实案例、授权素材、AI 概念和参考素材标签正确；
- 未泄露水印、内部模板号、提示词、调试字段、账号或敏感信息；
- 第三方素材、人物、音乐和字体有来源与授权记录；
- 输出比例、像素、格式、文件名和版本符合生产合同；
- 用户明确要求无文案时，成片没有被自动加入中文口号、英文装饰词、字幕或 CTA。

## 图片门禁

- 主体、施工细节、透视、材料和空间关系合理；
- 无畸形、重复物体、穿插、错误文字和不可能结构；
- 如有文字，手机端安全区、逐字正确和语言主次合格；
- 抖音 publish/l4 不接受普通视频抽帧冒充封面；必须有 1080×1440 的 3:4 主封面、同构的 1080×1920 首帧适配图和遮挡预览。
- 9:16 首帧适配图按当前批次在 `douyin-publish-package.md` 中锁定的布局规则检查；旧四边保守值和老板上下优先模式各按适用条件使用，不同时套两套留边值。关键主体和标题应兼顾居中 3:4 裁切。
- `publish-cover-report.json` 必须记录画布、预留、文字实际边界、正式封面、安全区预览和本地公开文字检查；`validate_cover_safe_zone.py` 返回 PASS。
- 抖音 9:16 批次只要存在正式封面，最终 MP4 第 0 帧必须由 HyperFrames 嵌入同一正式封面；独立上传封面不能替代视频首帧。仅接受有当前用户明确证据的 `in_video_cover_opt_out`。
- 安全区预览不得作为正式封面或视频内首帧来源。必须抽取实际帧 0、帧 1、封面停留中点、转场尾和场景进入帧，并让联系表包含实际帧 0。
- 实际帧 0 必须与正式封面做可复现 SSIM 或等效比较，达到报告声明阈值；黑帧、首帧被场景抢占、只有独立封面而没有视频首帧，均直接失败。
- AI 图明确标注概念，不作为真实完工证据；
- 交付前用原尺寸检查，不只看缩略图。
- 采用 [已确认封面设计](approved-cover-design.md) 时检查宋体实载、浅色细框、无衬底/字影/框影/模糊、实际字形边界及180px/360px缩图；不以正文苹方/两行旧规则改掉已确认封面。原生检查exit0不代表对比度通过；当前样片的低对比接受不豁免新图可读性检查。

## 抖音发布文字门禁

- 生成视频描述，并与话题组合成 `final/caption.txt`；描述不得编造案例、价格、工期、资质或保证性承诺。
- 正好 5 个不重复话题，必须包含 `#马来西亚装修公司`、`#马来西亚全屋定制`；另外 3 个分别覆盖内容主题、空间/风格和本地服务意图。
- 屏显文字、封面文字、视频描述和话题使用同一 `public_text_sha256`；任何修改后旧 Qingdou 结果失效。
- Qingdou 报告必须覆盖四类公开文字并保留证据；无可靠结果时保持 `HOLD`，本地检查不能冒充平台审核通过。
- `validate_douyin_publish_package.py` 必须返回 PASS。

## 视频基础门禁

- 六个核心产物共享当前 `task_id/run_id`，旧 QA、旧联系表和旧 final 没有被复用为当前证据；
- `creative-strategy.md` 明确 `input_mode`、`presentation_mode`、`copy_mode` 和选择依据；
- `video-contract.json` 已在调用固定模板前通过 `validate_video_contract.py`；
- 无跳帧、黑帧、卡顿、画面越界、音画错位或突然截断；
- 9:16、16:9 或 1:1 平台安全区合格；
- 完整渲染前已经检查开场、最亮、最暗、材质和转场中点代表帧；
- 成片按每个 scene 中点和每个切点检查，不用全片三个固定时间点代替逐镜 QA；
- 每个 scene 的曝光、白平衡和材质落在自己的 `grade_target`，相邻镜头无未经说明的亮度/色温突跳；
- 静态图片动效没有被命名为真实连续漫游；
- 正式 MP4 保留 ffprobe、技术检查和关键帧证据。
- 存在正式抖音封面时，`publish-cover-report.json`、首帧相似度报告和含帧 0 的联系表全部属于 final 门禁证据。

## `visual_music` 门禁

- `copy_mode=none` 时不要求脚本、字幕或文字钩子，也不因缺文案扣分；
- 运行全片 QC 时同时传入 `--video-contract drafts/creative/<task_id>/video-contract.json`；`visual_music/copy_mode=none` 必须把字幕可读性标为 `not_applicable`，但若实际发现字幕组仍须失败，禁止用缺字幕冒充字幕检查失败；
- 首 3 秒按画面入口、空间揭示、运动方向、构图信息量和音乐贴合评分；
- 使用 `visual_music` 专属评分表，不因缺少文案、英文、字幕或 CTA 扣分；实际出现这些内容则合同失败；
- 空间可读，镜头有呼吸，不为了追每个鼓点频繁切镜；
- 最强画面与音乐结构对应，高峰处没有被大段 CTA 遮挡；
- 无用户要求时没有英文；
- 必要的 AI 披露或品牌识别符合 `minimal_brand`，不演变成叙事文案。

## `minimal_brand` / `copy_led` 门禁

- 每项屏幕文字都有必要性，逐字正确；
- 按已确认的 [文字设计系统](premium-typography-system.md) 检查实际字体、轻字重层级、逐图留白、说明可读性与家具保护；每镜保留原尺寸和手机尺寸证据，不能仅用一张卧室样例代替全片检查；
- `copy_led` 的前 3–5 秒观看价值、字幕同步、事实和 CTA 清晰；
- `design_provisional` 没有被标成内容部已确认或可直接发布；
- 用户没有要求英文时，不用英文装饰版式制造“高级感”。

## 参考视频门禁

- 有可播放本地正文，而不是只有 URL、截图或描述；
- 有 ffprobe、contact sheet 和人工 `reference-analysis.md`；
- 已分析视频类型、首尾一秒、机位、空间路径、镜头长度、切镜、调色、文字密度和音乐；
- 原创方案没有复制参考作品的素材、品牌、水印、文案、音乐文件或完整顺序；
- 参考下载只用于授权允许的分析范围，没有被当作公司案例。

## 音乐四态门禁

各项分别记录真实结果；本项目制作使用决定按音乐流程单列 `owner_authorized_use`，不要求把未知版权记录改成 PASS 才能完成已授权的配乐制作。

| 状态 | 必要证据 | 失败条件 |
|---|---|---|
| `selected` | 具体文件、平台音乐 ID 或选曲记录 | 只有“建议音乐”没有具体选择 |
| `mounted` | 渲染工程/命令实际引用路径，或平台选曲记录 | 选了但工程未挂载 |
| `audible` | 人工全片听检 + 最终 ffprobe 音频流 | 无音频流、静音、过低、爆音、错轨或截断 |
| `rights_cleared` | 与目标渠道/用途匹配的授权证据 | 授权未知、仅同平台候选却用于跨平台/付费广告 |

`selected` 不能推导 `mounted`，`mounted` 不能推导 `audible`，可听也不能推导有授权。最终 MP4 没有音频流时，任何声称“已配音乐”的任务直接失败。

独立音乐权利核验还需匹配 `allowed_scopes` 和 `allowed_channels`；该证据筛查与老板已确认的全库制作使用分开，不重新引入逐首制作请示。

音频还需检查：

- 音乐时长覆盖或有合理剪辑；
- 开头/结尾无突切；
- 音量合适，不是技术上有音轨但实际听不见；
- 有配音时完成 ducking，无配音时音乐仍不过载；
- `music-map.json` 的高潮/能量段与实际画面基本一致。

## 放行结果

- `PASS`：可交渠道部门和老板审核；
- `HOLD`：质量可修复，或授权/事实/指定素材待补；
- `BLOCKED`：版权、真实性、事实、严重技术问题或未授权外部动作；
- `DRAFT`：只供方向预览。

部门内检通过后仍交 `qa`。设计部不能替 Reality Checker 最终放行。
