# 跨部门依赖编排

现行模式为 `goal_delivery_assistant_v1`：总部给完整目标、优先级和真实授权，专业主负责人沿同一任务执行到底，唯一具备对应能力且未参与制作的负责助理独立验收并落实已授权常规后续。总部读结论、定新目标，不重复技术审查。优先使用 `python3 tools/flashcast_ops.py dispatch-plan --request "..." --task-id <id>` 生成含依赖的本地计划。

## 标准执行波次

1. `wave_1`：没有前置依赖的事实/数据/brief 任务；按真实绑定与授权并行发送。
2. `wave_2+`：核 `depends_on` 的实际成果、原固定聊天非空回报和可读证据；ACK不替代成果，prepared不算sent。仅暂停依赖未齐的步骤，其他独立合法工作继续。
3. 专业主负责人连续完成已有授权和依赖齐全的步骤，结果只交唯一负责助理；禁止生产者自审。QA1/QA2保留历史证据，退出新派工。跨助理仅显式转给相同验收能力者，不串行全量复查。
4. 已授权常规后续由负责助理沿原授权来源、执行者、准确范围和既有合法通道落实，不逐段重新报审；新方向、重要授权变化或授权外动作交相应有权主体。`flashcast.com.my`常规R1/R2常驻授权保留原准确范围，R3及授权外动作仍按真实授权边界处理；网站执行后须公开复核并记录回执。真实生产仍须事实/必要自检、备份、可执行回滚及实际回执；CMS保存交publishing，代码/构建/部署交指定开发，Ads操作交付费部。助理验收不授账号、费用或跨项目权限，不绕401、issuer、单次许可或通道。
5. 部门当前轮次为 `active` 时，普通后续消息排队，保留原task/版本/hash/目标和恢复条件。负责助理用实际原生完成事件及原batch/cursor收取结果；队列不能唤醒已结束聊天，不为跟进新建高频轮询或监控窗口。不确定发送/保存/部署先核真实效果，显式恢复后才重试。

## 收益式委派和并发上限

部门波次与部门内子智能体是两层调度：协调者按现行责任向固定部门窗口派工；固定部门在确认接单后，才可为内部独立子问题调用短生命周期子智能体，不改变主负责人或唯一负责助理。

1. 先写明收益：`parallel_latency`、`specialist_capability` 或 `context_isolation`。
2. 相互依赖、同文件/同数据写入、外部动作和跨项目任务必须串行或阻断。
3. 全局最多 3 个，同部门最多 2 个；默认 900 秒超时，上限 1800 秒，最多 2 次尝试。
4. 终止状态与停止原因分别按委派政策记录，保留失败、超时、取消、依赖/政策阻断和无进展等真实原因，不将子智能体completed当作部门交付完成。
5. 子智能体完成只能作为固定部门的内部证据；固定部门必须自己回复、整合、写 outbox 并交唯一负责助理。

具体门禁以 `data/delegation-policy.json` 和 `data/task-contract.json#delegation_contract` 为准。

## 常见依赖

- Google Ads 审计：付费增长与转化数据取证，结果交具备对应能力的唯一负责助理；实际后续按原准确授权和付费通道执行。
- 广告文案/落地页：内容/SEO/网站成果与付费部搜索意图、message match 检查形成依赖；主负责人整合后交唯一负责助理。
- 转化异常：付费部与内容/网站可并行取证；需要业务真值时列销售确认依赖，整合结果交唯一负责助理。
- 获客图片/视频：内容brief和付费测试目标缺失时由视觉部列为依赖；具备真实输入后制作，结果交唯一负责助理。
- 全增长复盘：付费、内容和销售可并行；确需视觉时依真实brief/测试目标制作。整合结果交唯一负责助理，验收总结交总部知悉。

## 完成判定

部门交付须有真实发送、原固定聊天非空回传、准确结构化outbox/report、可读证据和需要的学习事件。负责助理按当前结果身份正式认领、收取、验收并记录实际下一动作回执或准确范围关闭；一个结果只允许一个有效处理人，保留既有token/fence/lease边界。候选、自检、验收、采用、实际Save/部署、公开复核和业务结果分别记录，子任务结束不关闭父目标。缺输入记录准确负责人、下一动作和解除条件，某批历史候选未采用不构成其他已授权业务的全局禁行。
