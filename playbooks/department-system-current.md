# 部门系统现行规则（2026-10-07）

本文件是总部、助理和所有注册部门共同遵守的现行组织与交接规则。与旧文件的部门数量、直接发结果消息、每天只做一项等描述冲突时，以本文件及最新机器合同为准。历史派工、许可、结果和业务主账保留原样；扩编不转移旧任务或外部权限。

## 一项任务怎么流转

1. 总部读取当前原任务和回执，选择最少必要部门；在任务包锁定候选版本、输入hash、范围、验收标准、交付路径及允许继续的步骤。核对真实项目/固定聊天/准确标题/cwd/分组、回复健康和精确路由后只派一次。
2. 部门先非空接单。执行明确授权范围；进度、结果和阻断均在自己的固定聊天报告。不得把计划、工具接受、文件数量或聊天idle当成果。
3. 部门在同轮报告完成、部分完成、QA返工、外部阻断、失败或入队失败；冻结V2 outbox，核实际聊天回复hash，唯一入队并回读。不直接给总部或助理发普通结果消息，不打断在途工作。

新V2必须在顶层填 task_id、department、fixed_chat_task_id、candidate_version、status，并在 chat_reply 中填准确固定聊天、原轮次、消息ID、真实回复SHA和观察时间。固定聊天字段必须来自现场核验，不从任意正文猜。先检查完整对象和原生派工/非空接单链，再保存最终版本、计算hash、登记收取和唯一入队；不要先用缺字段版本登记后再改原文件。老回执按兼容规则保留，新元数据补正必须用准确证据替换/新版本与新hash。

4. 助理仅占用总部派给它的准确结果；验证原聊天/outbox/QA/实施/公众复核，提交带证据的决策草案。一个结果只能有一个有效协调占用；中断恢复须检查过期占用、版本及已经发生的动作。
5. 总部核验后记录真实收取与明确决策：送准确QA、退原负责人最小返工、走合法实施门禁、继续下一有界工作、具名等待外部输入、或只关闭已验收范围。助理草案不等于controller_decision。
6. 每个决策必须关联真实下一动作：新派工回执、执行/公众复核回执、准确已有动作，或保管人/解除条件/下次复查时间。准备任务包不算已派出。未落实的决策继续在followthrough队列，不因pending_count为0消失。

## 减少等待，同时防止重做

- 部门正在active，普通下一任务排队；不得插话“继续”、重复派包或用同名新窗口替代。
- 总部派出本轮任务后以原生完成事件等待，沿cursor去重；自然接续点优先收新结果，再做维护。不一直重复read_thread，也不恢复五分钟定时检查。
- 已冻结任务包可以列出彼此独立、输入/范围/目录明确的同任务R0步骤。前一项交付后，部门按只读next-work检查器选择下一项；只有这些已授权步骤可以连续做，不自行发明生产许可。一个步骤失败只阻断依赖它的步骤。
- 有界任务的结果、最终outbox和唯一入队读回齐全后，无已授权下一步骤就结束该轮。不得为保持active自动加做日检、反复核对同一回报或制作无变化的补充日报；待审候选优先于例行日检。日检仍按自己的已授权窗口与优先门运行。
- 同候选版本不代表同工作。继续步骤必须匹配原派工包hash、步骤指纹和输入/输出范围；旧目录先回读恢复，不覆盖，不因换名字重做相同成果。
- 助理与总部并行只处理各自占用的准确结果。助理不抢最终决策，不并行重复派工；发送结果不确定时先回读真实聊天/回执，禁止盲目重发。
- 原生工具尚不提供“队列变化自动唤醒已结束总部”的能力。当前依靠本轮事件等待、自然接续和既有每日18:00兜底；不得把本地队列、角色文件或文案当成后台事件订阅。

## 日常专业循环

每个执行部门检查自己已做/未做、是否真正达标、是否有必要方法未考虑、为什么目标未达到，然后提出依赖齐全的下一批准确动作。优先已有返工和已PASS待实施，其次最高价值未完项，再检查新增机会。不能每天只交一份巡检报告而搁置可执行工作。

总控15:00汇总所有当前注册角色；18:00仅兜底漏报。不自动恢复暂停的例行自动化、不新增高频循环。专业执行仍由固定负责人在获准范围内完成；暂停、健康失败、权限缺失必须说明实际状态。

## 阻断与停止

| 路径 | 必须记录 | 后续条件 |
|---|---|---|
| 完成一轮 | 准确范围、实际产物/QA/执行层级、未完目标 | 总部决定下一项或只关闭已验收范围 |
| 部分完成 | 完成与未完分别列、依赖和唯一负责人 | 独立已授权R0步骤继续，其余由总部有界接续 |
| QA返工 | P0/P1/P2、原负责人、最小修复、必要检查、准确新版本 | 固定QA复验后才采用/发布；同阻断每天最多两次安全尝试 |
| 外部阻断 | 真正保管人、缺什么、解除条件、下次复查时间 | 只暂停依赖该输入的动作，其他安全工作继续 |
| 通知/入队失败 | 实际错误、原结果路径/hash和原轮次 | 修登记/绑定并核真实结果，不重做未变候选、不补造发送历史 |

每次总部停止前都留下“已完成/正在做/未完成/负责人/下一动作/停止原因”固定报告和最新检查点。内部候选、QA通过、读回、Saved、部署、公开复核和自然流量分别报告。50个自然来源去重IP/日仍按合法口径核验；没有真实数据写DATA_MISSING，未测AI效果写NOT_MEASURED。

## 发布与外部动作

候选QA不等于生产许可。CMS只走受保护后台和准确正文候选；代码只走Git/PR/CI/main/同SHA通道；地图只用原精确商家/动作/执行者/单次授权。QA2的R0控制准入不授权QA2代发布，也不替换旧QA签核或CMS issuer。批准、保存/部署和公众复核缺任一项都保留未完成。
