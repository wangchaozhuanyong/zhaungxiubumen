# 结果接续与总控结束前检查

适用项目：装修公司虚拟员工；只改变协调、回报与状态汇总，不增加任何生产或跨项目权限。

## 一个结果必须有四段证据

1. 部门在原固定聊天非空说明实际完成、未完、证据和唯一下一负责人；按最终 outbox 哈希入队。不得直接给工作中的总控插消息。
2. 总控核原聊天、任务、候选、哈希与 QA/执行层级后登记收取、决策。候选完成、只读 PASS、工作流 closed 只关闭准确已验范围。
3. 决策后关联真实下一次派工/实施/公开复核回执，或具名外部依赖、解除条件及下次复查时间。文件中写“交 QA”不等于 QA 已接单。
4. 本轮已派内部任务未结束时，总控通过原生 wait_threads 事件等待，单次不超过60秒并保存 cursor。超时只表示等待；结果队列文件不会唤醒已经结束的总控。部门结果结束后继续收取和决策，不能停在收到报告。

## 每次开始、停止前生成同一份进度表

先用应用现场唯一匹配核对全部注册角色身份，保存真实现场快照（observed_at、threads、sections），不得用注册表补造 projectId。

```sh
python3 tools/controller_progress.py \
  --live-proof logs/handoffs/<本轮>/native-nine-fixed-departments-live.json \
  --json-output data/controller-current-progress.json \
  --report-output reports/company-current-work-status.md
```

退出码0：本次控制范围无待接续项，仍不代表业务目标达成。退出码2：有在途、待收取、待 QA 派工或待关联后续动作，必须接续。退出码3：证据读取失败，先恢复证据。身份现场快照超过5分钟则重读；这不是五分钟轮询排程。

不可普通收工的情况：本轮内部任务仍 active；原在途任务已结束但尚未收取结果；有结果待决策；有依赖齐全的 QA 包未真实派发；有已决策未落实的可执行动作；业务主账存在 ready_for_qa、明确未保存/未公开复核子项或尚未核定负责人和解除条件的未完范围。历史 verified 父项不关闭这些子项。只有具名依赖、解除条件及未来复查时间齐全的外部等待可暂缓。负责人 active 只禁止普通消息插入，不能解释为工作完成。

若真实运行限制、额度失败或明确外部输入阻断迫使暂停，保留真实停止原因、原 task/版本/turn/cursor、负责人、解除条件和接续入口。不要把检查脚本描述成 Codex 应用硬锁，也不承诺结束后自动唤醒。

## 给老板的结束前说明

用简短表格报告：本轮实际做了什么；仍没完成什么；当前属于候选/QA/许可/保存或部署/公开复核哪个阶段；在途任务的准确 task_id、候选版本、turn_id；唯一负责人；下一动作与等待条件及复查时间。链接固定报告 reports/company-current-work-status.md。未更新全量生产证据时写“待复核”，不由旧 verified 或文件数推断全部完成。

结果队列中的多条控制记录按原任务、部门、候选和结果哈希去重。旧结果先对已有派工/实施证据，不重新要求部门制作同一候选，不伪造旧通知。旧控制记录数量不能当作网站问题数量。

## 部门协作

每个部门接续时读取本规则，按自己专业范围核对未完成项、遗漏方法和依赖，交准确下一步；跨部门由总控审核并派工，普通结果只入项目队列。技术候选由网站部制作、独立 QA；后台发布交 publishing；代码发布只沿老板指定开发聊天和精确门禁。专业内容/案例/价格/素材权利不足不编造。Ads HOLD/OFF/RM0、Maps 原边界、每日50自然去重IP DATA_MISSING 保持。

本规则配套工具只做读取与可控报告输出，不能授予消息或发布权限。验收必须另有固定 QA 的准确结果与至少一条真实部门结果→总控决策→真实下一动作链。
